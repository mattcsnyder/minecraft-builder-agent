# Minecraft Builder Agent

An AI-agent workflow for [Claude Code](https://claude.com/claude-code) that turns a natural-language
description into a fully-built Minecraft structure — no WorldEdit mod, no manual block placement.

Describe a build, and the agent will:

1. **Design** the structure and write it out as a `.schema` file of WorldEdit-style commands
   (`/pos1`, `/pos2`, `//set`, `//replace`, `/setblock`).
2. **Convert** the schema into a vanilla Java Edition **datapack** (a single `/function` you run in-game).
3. **Install** the datapack into your world's `datapacks/` folder.

Everything in this repo — the example builds, their schemas, and their datapacks — was produced
by this agent.

## How it works (the agent)

This repo ships two Claude Code slash commands in [`.claude/commands/`](.claude/commands/):

| Command | What it does |
| --- | --- |
| [`/minecraft-build`](.claude/commands/minecraft-build.md) | Takes your description, designs the structure (style, materials, layout), and writes a `<name>.schema` file. |
| [`/minecraft-datapack`](.claude/commands/minecraft-datapack.md) | Converts a `.schema` file into a datapack and helps you install it into one of your worlds. |

`/minecraft-build` calls `/minecraft-datapack` automatically once it finishes writing the schema,
so a single command takes you from idea → installed datapack.

### Usage

```
/minecraft-build a small viking longhouse with a thatched roof and firepit inside
```

The agent will:
- Pick a footprint, materials, and layout appropriate to the description (centered on X=0, Z=0,
  ground at Y=64, generally under an 80x80 footprint unless you ask for something bigger)
- Write `viking_longhouse.schema` with the full set of WorldEdit commands
- Convert it into a `viking_longhouse/` datapack folder
- Ask which of your Minecraft worlds to install it into, then copy the datapack into that
  world's `datapacks/` folder

## Deploying a build into the game

Whether a build was generated by the agent or you're installing one of the [examples](#examples)
below, the steps to get it into Minecraft are the same:

1. **Copy the datapack folder** into your world's `datapacks/` directory:
   ```
   <your world save>/datapacks/<name>/
   ```
   Worlds are typically found at:
   - `~/Documents/curseforge/minecraft/Instances/<instance>/saves/<world>/`
   - `~/Library/Application Support/minecraft/saves/<world>/`

2. **Load the world** (or run `/reload` in chat if it's already open).

3. **Run the build function** in chat:
   ```
   /function <name>:build
   ```
   `<name>` is the datapack's namespace — the same as the schema's base filename
   (e.g. `castle:build`, `wizards_tower:build`).

That's it — the function runs a sequence of `fill`/`setblock` commands that places every block.

> **Requirements:** Minecraft Java Edition 1.21.4+ (datapacks use `pack_format 71` and the
> singular `data/<namespace>/function/` directory introduced in 1.21.4). Cheats/commands must be
> enabled for the world (or run via an operator/command block).

## Repo layout

```
.claude/commands/        the two agent skills described above
tools/
  convert_to_datapack.py   .schema -> datapack converter (handles 32k-block fill limit)
  offset_schema.py         shifts every /pos1, /pos2, /setblock in a schema by (dx, dy, dz)
examples/
  <name>/
    <name>.schema          WorldEdit commands describing the build
    generate_<name>.py      (where present) the procedural Python generator that wrote the schema
    datapack/                ready-to-install datapack (pack.mcmeta + data/<name>/function/build.mcfunction)
```

`tools/offset_schema.py` is useful when you want to reposition a build before converting it —
e.g. to place several builds next to each other in the same world without overlapping:

```
python3 tools/offset_schema.py examples/castle/castle.schema examples/castle/castle.schema 0 0 100
python3 tools/convert_to_datapack.py examples/castle/castle.schema
```

## Schema format

A `.schema` file is a plain-text sequence of WorldEdit-style commands:

```
/pos1 -10,64,-10
/pos2 10,80,10
//set 75%stone_bricks,15%cobblestone,10%mossy_stone_bricks

/pos1 -8,65,-8
/pos2 8,79,8
//replace stone_bricks air

/setblock 0 70 0 lantern[hanging=true]
```

- `/pos1` / `/pos2` define a region's corners.
- `//set <block>` fills that region. Weighted specs like `75%stone_bricks,15%cobblestone` pick the
  dominant block when converted (the converter doesn't do randomized fills).
- `//replace <old> <new>` swaps blocks within the region (commonly used to hollow out interiors).
- `/setblock x,y,z <block>` places a single block.

See [`.claude/commands/minecraft-build.md`](.claude/commands/minecraft-build.md) for the full set
of design conventions the agent follows (materials by style, lighting, doorways, etc.).
